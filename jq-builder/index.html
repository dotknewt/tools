02  Choose records

Start at the root value, or select each item in an array. Path suggestions follow this source.

Use a JSON path array to distinguish an index from a numeric-looking key: [0] is an index, ["0"] is a string key. Quoted, dotted, empty, and prototype-named keys are supported.

03  Build the filter

GUIDED BUILDER

Conditions select input records first. Missing values and type mismatches do not match ordinary checks.

Empty AND matches all; empty OR matches none. For array checks, any is false and all is true on an empty array. NOT negates normally, including a missing-field non-match. A present null is different from a missing key.

Then transform

ORDERED STEPS

Steps act on the previous step's output. Emit changes its value; Update changes a path on the record.

Regex uses jq's Oniguruma syntax and flags (g, i, m, s, p, x). Match emits match objects; capture emits named groups. Update preserves the field for no matches and collects multiple matches into an array. Replacement text is literal except for \(.name) or quoted named fields such as \(.["first_name"]); arbitrary jq expressions are custom-only.

Choose output

Without a projection, the whole matching value is returned. Missing projected paths become null.

Write any jq filter supported by the bundled runtime. It runs once per input value; it is not parsed back into builder controls.
